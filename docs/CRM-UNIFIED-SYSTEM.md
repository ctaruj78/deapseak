# DeapSeaK CRM - Єдина система з рольовим доступом

## Проблема, яку вирішуємо

Раніше в проекті було **три окремі дашборди** для різних ролей:
- `/pages/admin/admin-dashboard.html` - для адміністраторів
- `/pages/dispatcher/dashboard.html` - для диспетчерів  
- `/pages/tech/dashboard.html` - для техніків

### Проблеми старого підходу:
❌ **Дублювання коду** - однаковий функціонал копіювався між файлами
❌ **Складність підтримки** - зміни треба було робити в 3 місцях
❌ **Неузгодженість** - різні версії могли відрізнятися
❌ **Зайвий QR функціонал** - техніки отримували аналітику, яка їм не потрібна

## Нове рішення

✅ **Єдина CRM система** (`/pages/crm-unified.html`)
✅ **Рольовий доступ** - кожна роль бачить тільки потрібний функціонал
✅ **Один код для підтримки** 
✅ **Логічний розподіл функцій**

## Структура нової системи

### Файли
```
/pages/crm-unified.html         # Головний HTML файл
/assets/js/crm-unified.js       # JavaScript з логікою ролей
/pages/crm-demo.html           # Демо-сторінка для тестування
```

### Рольовий розподіл функцій

#### 🔴 Адміністратор (admin)
- **Повний доступ** до всіх функцій
- QR система: генерація, управління, аналітика, пакетні операції
- Управління користувачами
- Налаштування системи
- Повна аналітика

#### 🟡 Диспетчер (dispatcher)  
- **Управління без налаштувань**
- QR система: генерація, управління, історія (БЕЗ аналітики)
- Призначення завдань техніками
- Моніторинг клієнтів
- Базові звіти

#### 🟢 Технік (tech)
- **Тільки необхідний функціонал**
- QR система: ТІЛЬКИ сканер (без аналітики та управління)
- Свої завдання
- Чек-листи та інструменти
- База знань

## Як використовувати

### Швидкий тест
1. Відкрийте `/pages/crm-demo.html`
2. Виберіть роль для тестування
3. Побачите різний інтерфейс для кожної ролі

### Інтеграція з аутентифікацією
```javascript
// В реальному проекті роль буде братися з JWT токена
const userData = await getCurrentUser();
window.location.href = `crm-unified.html?role=${userData.role}`;
```

### Параметри URL
- `crm-unified.html?role=admin` - вхід як адміністратор
- `crm-unified.html?role=dispatcher` - вхід як диспетчер  
- `crm-unified.html?role=tech` - вхід як технік

## Технічні особливості

### Система прав доступу
```javascript
// Приклад конфігурації прав
const permissionsByRole = {
  admin: {
    canCreate: true,
    canDelete: true,
    canViewAnalytics: true,
    canManageUsers: true
  },
  dispatcher: {
    canCreate: true,
    canDelete: false,
    canViewAnalytics: false,  // НЕ БАЧИТЬ QR аналітику
    canManageUsers: false
  },
  tech: {
    canCreate: false,
    canDelete: false,
    canViewAnalytics: false,
    canScanQR: true  // ТІЛЬКИ сканування
  }
};
```

### Динамічне меню
Меню генерується автоматично на основі ролі:

```javascript
const modulesByRole = {
  admin: ['dashboard', 'qr-full', 'users', 'settings'],
  dispatcher: ['dashboard', 'qr-basic', 'assignments'], 
  tech: ['dashboard', 'qr-scanner', 'tasks']
};
```

## Порівняння старої та нової системи

| Аспект | Стара система | Нова система |
|--------|---------------|--------------|
| Кількість файлів | 3 окремі дашборди | 1 універсальний |
| Підтримка коду | Зміни в 3 місцях | Зміни в 1 місці |
| QR для техніків | Зайва аналітика | Тільки сканер |
| Узгодженість | Можливі розбіжності | Завжди синхронно |
| Безпека | На рівні файлів | Рольовий контроль |

## Міграція зі старої системи

1. **Зберегти резервні копії** старих дашбордів
2. **Перенаправити** існуючі посилання на нову систему:
   ```javascript
   // Приклад редіректу
   if (window.location.pathname.includes('/admin/admin-dashboard.html')) {
     window.location.href = '/pages/crm-unified.html?role=admin';
   }
   ```
3. **Поступово видалити** старі файли після тестування
