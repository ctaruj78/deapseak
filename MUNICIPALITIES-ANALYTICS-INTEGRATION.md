# 🏛️ Муніципалітети в Unified Analytics - Інтеграція

## ✅ Що зроблено

Замість створення окремого dashboard для комунікацій з муніципалітетами, **інтегровано все в існуючу систему Unified Analytics**.

### 📊 Новий таб "Муніципалітети"

Додано новий таб в `pages/admin/unified-analytics.html`:

```
Огляд | Ліфти | ТО | QR Аналітика | Прогнозування | Фінанси | Інспекції | Користувачі | Звіти | Муніципалітети
                                                                                                      ↑↑↑↑↑↑↑↑↑↑↑↑↑↑
                                                                                                      НОВИЙ ТАБ
```

### 🎨 Що включає новий таб:

#### 1. **KPI Метрики** (4 картки)
- 🏛️ Всього муніципалітетів (37 concelhos, 120 km radius)
- ✅ Email відправлено (загальна кількість + зміна за місяць)
- ⚠️ Очікують повідомлення (pending notifications)
- 📊 Ліфтів з Municipality (% покриття)

#### 2. **Історія комунікацій** (таблиця)
- Муніципалітет
- Ліфт (municipal number)
- Тип повідомлення (novo elevador, inspeção, manutenção, etc.)
- Дата відправки
- Статус (sent/failed/pending)
- Дії (перегляд деталей)

#### 3. **Графіки**
- 🗺️ Розподіл по районах (Lisboa, Setúbal, Santarém, etc.)
- 📊 Типи повідомлень (bar chart)

#### 4. **Топ-10 муніципалітетів**
- Рейтинг за кількістю ліфтів
- Дані: Name, Distrito, Кількість ліфтів, Відправлено email, Відстань, Контакт

## 🚀 Як користуватися

### 1. Відкрийте Unified Analytics:
```
http://localhost:5000/pages/admin/unified-analytics.html
```

### 2. Перейдіть на таб "Муніципалітети"
Клікніть на таб з іконкою 🏛️

### 3. Дані завантажуються автоматично:
- Статистика з `/api/lifts` та `/api/municipalities`
- Історія комунікацій з `lift.municipality.notification_history`
- Топ муніципалітетів (сортування за кількістю ліфтів)

### 4. Оновлення даних:
Кнопка "🔄 Оновити" в правому верхньому куті картки історії

## 💡 Переваги інтеграції в Unified Analytics

### ✅ Переваги:
1. **Один dashboard для всього** - адміністратор бачить всю аналітику в одному місці
2. **Консистентний UI** - той самий стиль що й інші секції
3. **Менше коду** - використання існуючих стилів та компонентів
4. **Швидший доступ** - не треба переходити на окрему сторінку
5. **Спільна навігація** - одне меню для всіх типів аналітики

### ❌ Недоліки окремого dashboard:
1. Дублювання коду (sidebar, header, footer)
2. Додаткова навігація (ще одна сторінка в меню)
3. Непослідовний UX (різні стилі)
4. Більше файлів для підтримки
