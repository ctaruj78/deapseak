## 🏗️ АРХІТЕКТУРА ПРОЄКТУ

### Стек
- **Backend**: Node.js + Express (`unified-server.js`)
- **Database**: MongoDB + Mongoose (`models/`)
- **Auth**: JWT (access + refresh tokens)
- **Real-time**: WebSocket
- **AI**: Google Gemini 2.5 Flash (`gemini-2.5-flash`)
- **PDF**: pdf-parse + Gemini Vision OCR (`services/pdf-ocr-gemini.js`)
- **Frontend**: Vanilla JS, HTML, CSS (без фреймворків)
- **Language**: Португальська (PT-PT) — всі тексти інтерфейсу

### Головні файли
| Файл | Призначення |
|------|-------------|
| `unified-server.js` | Єдиний сервер — API + frontend + WebSocket |
| `services/pdf-parser-enhanced.js` | Парсинг PDF звітів інспекції ліфтів |
| `services/pdf-ocr-gemini.js` | OCR сканованих PDF через Gemini Vision |
| `services/agentService.js` | AI агент для чату та аналізу |
| `models/` | MongoDB схеми (Lift, User, Report, тощо) |
| `pages/` | HTML сторінки по ролях (admin/dispatcher/technician/client) |
| `autostart.sh` | Єдиний скрипт запуску всього проєкту |

## 🤖 ПРАВИЛА ВИКОРИСТАННЯ AI (GEMINI)

### Модель
- **ЗАВЖДИ**: `gemini-2.5-flash` — оптимальний баланс ціна/якість
- **НІКОЛИ**: `gemini-3-flash-preview` або платніші preview-моделі без явного дозволу користувача
- Якщо модель змінюється — ПОПЕРЕДИТИ про різницю у вартості

### Промпти
- Температура для структурованого виводу: `0.1` (майже детерміністично)
- Температура для чату/відповідей: `0.7`
- Для JSON-виводу: явно вказувати формат і `maxOutputTokens: 8192`
- OCR DPI: мінімум **400** (не менше!)
- Завжди обробляти markdown-обгортку яку Gemini може додати до JSON

### Стратегія парсингу PDF
1. `pdf-parse` — витягує текст з текстових PDF
2. OCR через Gemini Vision — для сканованих (< 200 символів із pdf-parse)
3. `extractStructuredWithGemini` — **обов'язковий** третій шар поверх regex
4. Regex — fallback, ніколи не єдине рішення для складних документів

## 🔐 БЕЗПЕКА

- JWT токени: access (15хв) + refresh (7 днів)
- Паролі: bcrypt, мінімум 10 rounds
- API ключі: **ТІЛЬКИ** через `process.env`, ніколи хардкод
- Всі admin-endpoints мають middleware `authenticateToken` + `requireRole('admin')`
- Rate limiting на auth endpoints
- Sanitize всіх вхідних даних перед MongoDB запитами

---

## 🗄️ БАЗА ДАНИХ (MongoDB)

- Завжди використовувати Mongoose схеми з валідацією
- Індекси на поля які часто фільтруються (liftId, userId, date, status)
- Ніколи не зберігати паролі у відкритому вигляді
- Transactions для операцій що змінюють кілька колекцій
- `lean()` для read-only запитів (продуктивність)

## 📄 ПАРСИНГ ДОКУМЕНТІВ (PDF)

- Підтримувані формати звітів: GATECI, CERTIEL, NOMINARE, Bureau Veritas, IEP
- Класифікація порушень: **C1** (критично), **C2** (середнє), **C3** (низьке)
- Юридична база: Decreto-Lei n.º 320/2002, Portaria n.º 231/2004
- Португальські символи **ОБОВ'ЯЗКОВО** зберігати: ã â á à ç é ê í ó ô ú ü
- Після кожного парсингу — логувати кількість знайдених порушень (C1/C2/C3)

## ⚡ ПРОДУКТИВНІСТЬ

- Кешувати результати Gemini де можливо (однаковий документ = один запит)
- Паралельні запити замість sequential де незалежні операції
- Стримінг відповідей Gemini для довгих текстів
- PDF обробка — завжди tmpdir + cleanup після завершення
- MongoDB запити — aggregate замість N+1
