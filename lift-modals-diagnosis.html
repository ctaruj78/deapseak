🔧 Діагностика проблем з модальними вікнами ліфтів

🚨 Виявлені проблеми

Проблеми з модальними вікнами:
  1. ТРИ модальних вікна: liftModal, enhancedLiftModal, liftDetailsModal
  2. Дублювання полів ТО: різні ID для однакових даних
  3. Різна логіка збереження: кожне вікно зберігає по-своєму
  4. Несинхронізація даних: дані не показуються в списку

#liftModal (Простий)

Поля ТО:
  • lastMaintenance - Останнє ТО
  • nextMaintenance - Наступне ТО
Збереження:

localStorage.setItem('lifts', ...)

Статус:
Не використовується

#enhancedLiftModal (З картою)

Поля ТО:
  • enhancedLastInspection - Остання інспекція
  • enhancedNextInspection - Наступна інспекція
Збереження:

window.allLifts + CommonUtils.saveLifts

Статус:
Використовується (кнопка "Додати ліфт")

#liftDetailsModal (Перегляд)

Поля ТО:
  • Тільки відображення даних
  • Не редагує
Збереження:

Не зберігає

Статус:
Тільки перегляд
🔍 Аналіз проблеми:

Головна проблема: Кнопка "Додати ліфт" використовує enhancedLiftModal, але поля ТО мають інші ID ніж очікує таблиця.

Таблиця очікує:

  • Останнє ТО: lastMaintenance
  • Наступне ТО: nextMaintenance

enhancedLiftModal має:

  • Остання інспекція: enhancedLastInspection
  • Наступна інспекція: enhancedNextInspection

✅ Варіанти рішення

🎯 Варіант 1: Уніфікація полів

План:
  1. Перейменувати поля в enhancedLiftModal:
    • enhancedLastInspection → lastMaintenance
    • enhancedNextInspection → nextMaintenance
  2. Оновити логіку збереження
  3. Видалити простий liftModal (не використовується)

🔧 Варіант 2: Правильна синхронізація

План:
  1. Додати маппінг полів при збереженні
  2. Оновити функцію відображення в таблиці
  3. Синхронізувати всі джерела даних
  4. Зберегти існуючі назви полів
💡 Рекомендація:

Варіант 1 (Уніфікація) - найкращий підхід:

  • Видаляє дублювання
  • Спрощує логіку
  • Одні назви полів скрізь
  • Легше підтримувати
